# Анкета QR-подарка `/gift`

- Production: `https://mishanya-show.com/gift?src=banner-01`.
- Страница закрыта от индексации и не содержит WhatsApp-призыва.

## Локальная работа

- Страница: `http://localhost:3003/gift?src=banner-01`.
- В `npm run dev` отправка работает через локальный mock и ничего не записывает в Bitrix или Cloudflare.
- На странице показывается единственный подарок — скидка `200 ₪`. Анкета видна сразу, без открытия модального окна; конфетти и шоу пузырей не предлагаются и не принимаются в новых заявках.
- Скидка сохраняется в `localStorage` по введённому номеру после удаления пробелов по краям.
- Повторная отправка с тем же номером показывает уже закреплённый подарок и не меняет его. Старые записи с прежними подарками продолжают корректно отображаться.
- Шесть обязательных ответов идут в порядке: телефон WhatsApp, имя клиента, пол ребёнка, возраст на ближайший день рождения, день и месяц рождения, город. Имя ребёнка, год рождения и ведущий не запрашиваются.
- Поле «Ваше имя» / «השם שלכם» обязательно, поддерживает автозаполнение `given-name` и читается из `FormData`. Пробелы по краям удаляются; имя из одних пробелов не принимается.
- Пол и возраст (1–10) выбираются крупными кнопками, дата — двумя списками без года. Список дней всегда содержит 1–31, независимо от выбранного месяца; смена месяца не стирает день. Несуществующие сочетания (например, 31 апреля) проверяются при отправке и показывают понятную ошибку. 29 февраля разрешено.
- Город можно ввести свободным текстом. При наборе над полем открывается список совпадений с прокруткой; выбор работает мышью, касанием и стрелками с Enter, Escape закрывает список. Поиск не зависит от регистра, пробелов и дефисов. Подсказки из проверенного справочника BitrixCheckup находятся в `data/gift-cities.ts`: 138 названий на русском, 106 имеющихся в источнике названий на иврите. Выбирать пункт из списка не обязательно. Список включает посёлки и районы и не означает подтверждённую доступность выезда.
- Над формой прямо указано: для закрепления скидки нужно заполнить форму и нажать кнопку отправки.
- Телефон принимает любой непустой текст без проверки формата и нормализации. Пробелы по краям удаляются.
- Поле использует `type="tel"`, `inputmode="tel"`, `name="tel"` и `autocomplete="tel"`, а форма разрешает автозаполнение. Браузер может предложить ранее сохранённый номер; сайт не получает номер SIM-карты и не гарантирует предложение на каждом устройстве. При отправке номер читается из `FormData`, в том числе после автозаполнения.
- Русский и ивритский тексты объясняют, что ответы нужны для подбора программы и закрепления скидки. При локальной проверке внешние запросы в CRM не выполняются; защита Turnstile в режиме разработки не загружается.

## Что записывается в Bitrix после подключения

Для новой краткой анкеты:

- `PHONE` — телефон ровно в том виде, как его ввёл клиент, после удаления пробелов по краям; тип `WORK`, который используют WhatsApp-роботы Bitrix24;
- `NAME` — имя клиента после удаления пробелов по краям, также добавляется в заголовок лида;
- `UF_CRM_1666781395585` — `808` (`День рождения`);
- `UF_CRM_1784446465040` (`Выбранный подарок`) — `Скидка 200 ₪`;
- `ASSIGNED_BY_ID` — `3828` (Сергей);
- новый лид создаётся на первой стадии `Новый лид` (`STATUS_ID = NEW`);
- `SOURCE_ID` — `REPEAT_SALE` (`QR-код с праздника`);
- `COMMENTS` — видимое в карточке поле `Заметка`.
- `UF_CRM_1644328015350` — город;
- `UF_CRM_1644327962757` — пол ребёнка (`44` / `46`);
- `UF_CRM_1644329391894` — сколько исполнится лет;
- `BIRTHDATE`, `UF_CRM_1649234588017` — ближайший день рождения, вычисленный по дню и месяцу;
- `UF_CRM_1644332749977` — «Ждать до» по существующему правилу обработчика.

В `Заметке` сохраняются дата анкеты, подарок и найденные совпадения по телефону. Дата окончания действия подарка, телефон, язык интерфейса и носитель QR там не дублируются. Ведущий и другие отсутствующие в анкете сведения не придумываются.

Обработчик сохраняет совместимость с полными анкетами прежней версии, в том числе уже зашифрованными заявками в очереди. Если переданы имя, город, утверждённый ведущий и дети, прежняя проверка и заполнение соответствующих полей сохраняются. Основным становится ребёнок с ближайшим будущим днём рождения; остальные дети попадают в заметку. Служебные подписи всегда на русском, имена и города сохраняются на языке клиента.

Новая форма всегда передаёт `clientName`; явно переданное пустое имя отклоняется с `invalid_client_name`. Старые формы без этого поля продолжают приниматься, чтобы не ломать уже открытые страницы и прежние заявки.

Интеграция не меняет стадию после создания и не переносит лид в реактивацию. Worker проверяет источник и при необходимости восстанавливает его. Для анкеты с днём рождения `Ждать до` рассчитывается за 32 дня, а при попадании на субботу — за 31 день. Старые заявки с одним телефоном по-прежнему поддерживаются; при их повторной синхронизации существующие даты в CRM не очищаются и не меняются. Дальнейшее решение по каждому новому лиду Сергей принимает вручную.

## Защита от дублей

1. D1 проверяет активный подарок по HMAC-хешу введённого телефона после удаления пробелов по краям. Разные варианты написания одного номера считаются разными значениями.
2. Пока подарок действует, новый выбор не перезаписывает его.
3. Bitrix проверяется через `crm.duplicate.findbycomm`.
4. Для каждой новой действительной анкеты создаётся новый лид на первой стадии.
5. Существующие лиды, контакты и компании автоматически не обновляются и не связываются.
6. ID найденных карточек записываются в `Заметку`, чтобы Сергей принял решение вручную.
7. Повторная отправка той же анкеты защищена внешним ID и не создаёт второй лид.

## Надёжная доставка

1. Pages Function валидирует анкету и первой операцией сохраняет её в D1.
2. Turnstile проверяется, когда защитный виджет доступен. Если браузер блокирует его, форма продолжает работать: спам ограничивают скрытое поле-ловушка и лимит 12 попыток с одного IP в час в D1.
3. В очередь `mishanya-gift-sync` отправляется только ID анкеты без персональных данных.
4. Worker расшифровывает запись, проверяет дубли и создаёт лид в Bitrix.
5. При временной ошибке сообщение повторяется до 10 раз и затем попадает в `mishanya-gift-sync-dlq`.
6. `ORIGINATOR_ID` + `ORIGIN_ID` защищают от повторного создания лида при повторной доставке сообщения.

## Cloudflare bindings и secrets

Pages project `mishanya-site`:

- D1 binding `GIFT_DB` -> `mishanya-gift`;
- Queue producer binding `GIFT_SYNC_QUEUE` -> `mishanya-gift-sync`;
- encrypted secrets `GIFT_DATA_SECRET` и `TURNSTILE_SECRET_KEY`;
- GitHub variable `NEXT_PUBLIC_TURNSTILE_SITE_KEY`.

Worker `mishanya-gift-sync`:

- D1 binding `GIFT_DB` -> `mishanya-gift`;
- Queue consumer `mishanya-gift-sync`;
- encrypted secrets `GIFT_DATA_SECRET` и `BITRIX_WEBHOOK_URL`;
- variable `BITRIX_QR_SOURCE_ID = REPEAT_SALE`.

Production workflow обязан публиковать и Cloudflare Pages, и Worker `mishanya-gift-sync`. Изменения `../shared/gift-core.js` не попадают в обработчик очереди, пока Worker не выполнит отдельный `wrangler deploy`.

Для выбранного подарка используется пользовательское поле лида `UF_CRM_1784446465040`. Все секреты хранятся в Cloudflare и не попадают в GitHub или клиентский JavaScript.
